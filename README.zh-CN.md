<h1 align="center">Clear Chat</h1>

<p align="center">Clear Chat 是 <a href="https://paseo.sh">Paseo</a> 的插件。它保留回答卡片：回复里有字母选项题时，用卡片选题或自己写答案，预览后发送。这一版给 <b>我说的话</b> 的每一行加了操作：左边栏打开的整页会列出你今天说过的话；每一行都有 <b>复制</b> 和 <b>引用</b>，点一行会打开那条消息所在的对话。Clear Chat 不绘制对话。对话显示请用另一个插件 <a href="https://paseo.sh/plugins/roundreddot/better-paseo">Better Paseo</a>。</p>

## 这一版

Clear Chat 0.17.5.2 跟上 Paseo 0.17.5：版本号前三段就是这一版对应的 Paseo 版本，第四段数的是 Clear Chat 在该 Paseo 版本上的第几次发布。这一版给 **我说的话** 的每一行加了操作，并去掉了对话头部的 **我说的话** 按钮和对话旁的面板：今天说过的话改用左边栏 **我说的话** 一行打开的整页来看。整页里点一行会打开那条消息所在的对话（同一台宿主）；宿主没有客户端导航时，点一行仍然是复制这条消息。每一行都有 **复制** 和 **引用**：**复制** 把原消息复制下来并弹出「已复制」；**引用** 会把焦点放到那条消息所在的对话输入框，把消息按 Markdown 引用插到光标处——每行前面加 `> `，空行变成 `>`，消息前后的空行去掉，末尾留一个空行。对话没有输入框时（已归档的对话，或宿主不提供输入框），整页会打开那个对话并把引用复制下来，提示「无法将引用插入此对话，已复制引用」。没有文字的消息，**复制** 提示「这条消息没有文字可复制」，**引用** 提示「这条消息没有文字可引用」。回答卡片没有变，也没有新的设置。限制写在[已知限制](#已知限制)：只列今天；整页点一行打开的是对话，不跳到那一条消息；**引用** 插在光标处，不替换已有草稿；已归档的对话只能把引用放到剪贴板；daemon 刚重启时打开整页每个要从存储恢复的对话约一秒（Codex 实测；测试用 provider 约 4 秒一个）。

完整改动见 [变更记录](CHANGELOG.md)。

## 回答卡片

有字母选项题的回复生成完之后，输入框上方会出现一个按钮。按钮上带着进度，例如 **回答 0/2**。桌面上鼠标停在上面能看到完整名称 **回答卡片 · 已答 0/2**；窄屏上点开的面板标题就是这个名字。点它把整张卡片打开成面板；窄屏上是从底部升起的面板。桌面面板里，题目区在卡片内滚动，进度行和 **发送** 固定在底部同一行，不用滚动面板就能看到 **发送**。在面板里选好答案，按卡片上的 **发送**：消息像你亲手发的一样进到这个对话，输入框里正在写的内容不受影响。每答一题，按钮上的数字跟着变（**回答 1/2**）；关掉面板再打开，答案还在；发送之后按钮消失，等下一段有字母选项题的回复完成后再出现。已经答了一部分时发一条普通消息，按钮仍然留在输入框上方带着进度；点开卡片就是 **继续作答**，按下去存下的草稿就回来了。按钮只属于当前对话：换到别的对话，显示的是那个对话自己的卡片，没有就不显示。

打开 **Settings → Plugins → Clear Chat**。页面主标题是 **Clear Chat**，第一张设置卡的标题是 **回答卡片**。设置文件里没有存过开关时，**在包含字母选项问题的回复下显示回答卡片** 是开的。已经存过的开或关仍然有效。开关下面的说明是：重新加载聊天以更新现有回复。

卡片本身的操作如下。

回复要同时满足这些条件才会被认成题：有编号的问题，每题至少两个字母选项（`A`–`H`，也包括全角 `Ａ`–`Ｈ`），并且有推荐标记，或有「reply with」「answer with」这类要求简短作答的提示。代码块和引用里的行不看。同一题里字母必须往前排（`A` 然后 `C` 可以；`B` 然后 `A` 不行）。`（推荐）` 或 `(recommended)` 会认出来；「not recommended」和 `不推荐` 不会。选项下面单独一行、只点一个选项（这一行没有别的字）的推荐，例如 `Recommended: A`、`推荐：A`、`おすすめ：A`，会标出这个选项，不算进上面那个选项；标记可以带句号，也可以加粗。日文的标记后面要有冒号或空格。像 `不推荐：A` 这样的一行不会被当成推荐，这一行按普通文字保留。

1. 点一个选项；焦点在卡片里时也可以按对应字母。还可以用 **↑/↓** 移动，按 **Enter** 选定。在 Paseo 输入框里按的键仍归输入框。
2. 答完一道还没答的题，会到下一道还没答的题。最后一道选定后，焦点到 **发送**。没答齐时，**发送** 会标出还缺哪一题，并且不能按。
3. 题签显示问题的短名。不是当前题、但已经答过的题签显示 `✓` 和答案。改一道已经答过的题时，停在这一题。
4. 要自己写，选 **自己写**。**Enter** 确认并往后走，**Shift+Enter** 换行。输入法选字不会确认。空着会提示先写答案。
5. **发送** 显示字母索引，例如 `1B 2A`。自己写的答案按你确认的文字放进消息。桌面面板里，自己写的答案在底栏上方最多预览两行：第一行是完整的答案编号，第二行是第一个自己写的答案的开头；发出的消息仍保留完整答案。发送成功后按钮消失，卡片不再显示；对话里那条消息（例如 `1B 2A`）就是你的回答。
6. 普通列表被误认成题时，点 **不是选项**。这条回复在重新加载后仍保持收起。发送过程中没有这个按钮。
7. 在设置页编辑的常用回答，会在卡片上变成按钮。桌面面板里它们在选项下面，跟着题目一起滚动。点一下把短语插到光标处，不会发送。

句子里单独出现的一个字母不当成答案，例如 “wait a moment”。带编号的记号仍然算，例如 `1A`、`2b`、`Q1A`，旁边有标点也算（`1A.`）。整条消息就是答案时不变，包括只有一道题、整条消息是 `b` 的情况。`Plan 2B` 这样的消息仍可能被当成答案。

## 我说的话

**我说的话** 列出你今天发过的消息，范围是本机的各个对话。它是左边栏头部一行打开的整页；每一行都有 **复制** 和 **引用**，点一行会打开那条消息所在的对话。宿主没有客户端导航时，点一行是复制这条消息。

### 我说的话整页

整页读本机各工作区的对话：左边栏头部的 **我说的话** 一行点开就是整页，列出本机各对话里你今天打过的消息，也就是设备本地的日历日，今天归档的对话也算在内。手机宽度下这一行在侧栏抽屉里，列表不会横向溢出。

顶上一行数今天，例如 `今天你发了 12 条消息 · 来自 3 个对话`。读取时显示「正在读取对话列表…」，随后是「正在读取对话（3 / 7）…」，每读完一个对话就先出它的行，所以整页还没读完就能看、就能复制。每一行是对话名、本地时间（`HH:MM`）和最多三行正文；点一行会打开那条消息所在的对话（同一台宿主）。宿主没有客户端导航时，点一行改为复制这条消息。每一行还有 **复制**：把消息按原样复制并弹出「已复制」；以及 **引用**：把消息按 Markdown 引用插到那一行所在的对话。对话没有输入框时，**引用** 会打开对话并把引用复制下来，提示「无法将引用插入此对话，已复制引用」。没有文字的消息，**复制** 提示「这条消息没有文字可复制」，**引用** 提示「这条消息没有文字可引用」。没有对话名时显示「未命名对话」。

- **引用** 会把焦点放到那一行所在的对话，把消息插到光标处：每行前面加 `> `，空行变成 `>`，消息前后的空行去掉，末尾留一个空行；不替换已有草稿。
- **刷新** 会重新列对话目录，并从空列表重新填：今天已经读过的对话会很快回来。列表只读了一部分、或有对话读不到时会出现 **重试**，它走同一遍流程，区别是给读了一部分或读失败的对话加倍页数上限，最多到上限。
- 只要有读不完、读失败、宿主给不出历史的情况，整页就写「消息列表可能不完整。」；读不到历史的对话由单独一行计数，例如「今天有 3 个对话读不到历史。」这些对话不缓存，**刷新** 和 **重试** 都会重读。
- 整页开着过了本地午夜，下一次滚动或点按才会写明这些是前一天的消息，按 **刷新** 才换成今天的。
- 别的 Agent 开的对话不列，**在这种子对话里直接打的字也一起不列**。provider 不可用的对话宿主不会列出，整页也就读不到。
- 读一个还没载入的对话，会让 daemon 把它从存储里载入，占时间和内存，直到 daemon 空闲回收。
- 实测打开速度（Paseo 0.17.4、真实 provider：Codex）：20 个对话都已载入时 0.38 秒读完；daemon 刚重启、20 个都要从存储恢复（其中 5 个已归档）时，同一批 20.4 秒读完，约一秒一个。不需要模型的测试 agent 从存储恢复约 4 秒一个，所以别的 provider 可能更慢。读的时候每读完一个对话就先出它的行。这些是在这些条件下的实测数字，不是对其他宿主或 provider 的保证。

## 安装

Clear Chat 0.17.5.2 需要 Paseo 0.16.0 或更新。在 Paseo 0.15.x 上这一版无法正常安装或运行，请留在 Clear Chat 0.15.4.x。这一版的浏览器检查跑在 Paseo 0.17.5 上；没有在 Paseo 0.16.x、0.17.1、0.17.2、0.17.3、0.17.4 上检查。安装命令没有在 Paseo 0.16.x 上检查过；Paseo 0.16.0 和 0.16.1 没有检查。Paseo 0.17.5 上查的是「我说的话」整页：点一行会打开那条消息所在的对话，包括已归档的对话和第二台宿主上的对话；**复制** 把消息复制下来、不会打开那一行；**引用** 插进那一行所在的对话，另一个对话的草稿不受影响；已归档对话的退回会打开对话并复制引用、弹出提示；390 宽下按钮高 44px、都在视口内；简体中文标签正确；控制台没有插件报错。第一个检查的提交按钮高 36px；第二个提交把它提到 44px，并让 **引用** 跳过空消息、去掉引用前后的空行、聚焦后重新读取输入框。检查过的提交之后，引用改为逐行生成，**引用** 有了自己的空消息提示，都有单元测试。之后 `80a0dba` 删掉了头部按钮和面板，`9618fe4` 只收窄引用动作的类型、行为不变。删面板的提交 80a0dbaa 上又跑了一轮浏览器检查：对话头部没有 **我说的话** 按钮、没有面板，左边栏那一行还在；点一行能打开对话和已归档的对话；**引用** 插进那一行所在的对话、另一个对话的草稿不受影响；**复制** 复制消息、不打开那一行；390 宽下按钮 51×44 和 56×44、都在视口内；设置页显示版本 0.17.5.2；控制台没有插件报错。回答卡片没有变。也在 macOS 的 Paseo 0.17.5 桌面 app 上查过，见下文的检查清单。

```bash
paseo plugin install git:jasonhnd/paseo-clear-chat --ref v0.17.5.2
```

安装会在 daemon 主机上运行 `npm ci --include=dev --ignore-scripts`，所以那台机器要有 Node.js 和 npm，并且能连到 npm 仓库。

把已经安装的 Clear Chat 更新到这一版：

```bash
paseo plugin update clear-chat --ref v0.17.5.2 --yes
```

打开 **Settings → Plugins → Clear Chat**，看 **回答卡片** 卡片里的版本行。从目录安装时会沿用该目录里已有的版本信息，因此可能显示旧版本。构建里没有可用版本时，这一行显示 **未知**。

## 升级与回退

```bash
paseo plugin update clear-chat --ref v0.17.5.2 --yes
```

升级会保留设置文件。回答卡片、常用回答、被收起的误认，以及没写完的草稿都会留下。存下来的草稿里，坏掉的、旧形状的、或形状不认识的记录会在读取设置时被忽略（这条记录留在文件里，等下一次写入设置才消失）；其它草稿和你的偏好照常读出来，设置页也不会再因为这一条把整个文件报成无效。这一版不再显示的功能，它们的键还在文件里，设置页上没有对应控件。退回更早的 ref 一般也保留文件，但某一次回退对设置的影响没有保证，设置重要的话先备份。升级后对话头部不再有 **我说的话** 按钮，对话旁边也没有面板；今天说过的话在 **我说的话** 整页里看。退回上一版会保留设置，并让头部按钮和面板回来，整页的行会退回只能复制，因为那一版没有 **复制** 和 **引用** 按钮。退回更早的版本，存下的选项还在，但那一版会忽略 `resumed: true`，点过 **继续作答** 的卡片刷新后要再点一次 **继续作答**。卸载插件会删掉它的设置。

更新之后，对话不再由 Clear Chat 绘制。对话显示用 [Better Paseo](https://paseo.sh/plugins/roundreddot/better-paseo)。你不会再看到 Clear Chat 的步骤行、工具卡、侧边栏。

回答卡片从输入框上方的按钮打开。更新后，有字母选项题的回复生成完，输入框上方就会出现按钮，例如 **回答 0/2**；桌面上鼠标停在上面能看到完整名称 **回答卡片 · 已答 0/2**（窄屏上点开的面板标题就是它），点它打开卡片。

启动时不会删除插件数据目录里的任何东西。以前的图片和历史目录会留在原地。这一版不用它们。

## 设置

页面主标题是 **Clear Chat**，第一张设置卡的标题是 **回答卡片**。

| 设置 | 作用 |
|---|---|
| 在包含字母选项问题的回复下显示回答卡片 | 没有存过值时为开。存过的值仍然有效。开关下的说明是重新加载聊天以更新现有回复。 |
| 常用回答 | 每行一个短语。默认是 `Go with the recommended`、`Leave it for now`、`Continue`。在回答卡片上点一个短语会插入，不会发送。在这里改完，离开输入框就保存。 |

**已安装版本。** **回答卡片** 卡片里显示这次安装所用构建的版本。从目录安装时会沿用该目录里已有的版本信息，因此可能显示旧版本。没有可用版本时显示 **未知**。

**报告问题** 会在浏览器里打开 GitHub 的问题表单。你不提交，就什么都不会发出。

设置保存在主机上，连到这台主机的客户端都共用。

## 语言

Clear Chat 自己的文字跟随 Paseo 的应用语言：英文、简体中文、日文。设置页、回答卡片和 **我说的话** 整页都已翻译。Paseo 自己的文字仍用 Paseo 的语言，agent 的输出从不翻译。插件列表显示英文说明。

## 已知限制

- **我说的话** 整页只读今天，也就是设备本地的日历日；更早的日子不列。
- 整页列出本机上你最后一条消息在今天的对话，归档的也算；别的 Agent 开的对话不列，**在这种子对话里直接打的字也一起不列**。
- provider 不可用的对话宿主不会列出，整页也就读不到。
- 某些 provider 从存储恢复后给不出历史。这类对话不列出来，而是由「今天有 N 个对话读不到历史。」单独计数；它们不缓存，**刷新** 和 **重试** 都会重读。
- 只能发现今天的历史整段丢失；丢一部分时不提示，整页照 provider 给回的列出。
- 读未载入的对话会让 daemon 把它载入，占时间和内存，直到 daemon 空闲回收。
- 真实 provider（Codex）下，20 个对话都已载入时 0.38 秒读完；daemon 刚重启、20 个都要从存储恢复时，同一批 20.4 秒读完，约一秒一个。测试 agent 从存储恢复约 4 秒一个，所以别的 provider 可能更慢。这是在 Paseo 0.17.4 上测到的，不是对其他宿主的保证。
- 整页里点一行会打开那条消息所在的对话，不跳到那一条消息：插件 API 没有滚动到消息的接口。
- 已归档的对话没有输入框：整页里 **引用** 会打开对话并复制引用。
- **引用** 插在光标处，不替换已有草稿。
- 宿主没有客户端导航时，整页点一行是复制这条消息，不打开对话。
- 只有图片的行没有可复制、可引用的文字：**复制** 提示「这条消息没有文字可复制」，**引用** 提示「这条消息没有文字可引用」。
- 机器消息按开头文字识别，所以一条因为别的原因也用这种开头的人话会被算成机器消息，不会列出来。
- 一天有页数上限。没读完时整页会说明消息列表可能不完整，并给出 **重试**（最多到上限）；这时计数是下限，至少是列出的行数。
- `Plan 2B` 仍可能被当成答案。句子里的单个字母不会。
- 桌面面板里，长的自定义答案最多预览两行：第一行是完整的答案编号，第二行是第一个自定义答案的开头。发出的消息保留完整答案，窄屏面板照旧完整显示；太长时窄屏面板里可能要滚动才能看全。
- 窗口矮于约 117px 时不支持：面板的底栏已经放不下。
- agent 正在回答时，仍可编辑的卡片在输入框上方没有按钮；已经打开的面板会说明回复还在生成，回答结束后按钮和作答一起回来。仍在等你作答的只读卡片照旧显示按钮。
- agent 刚开始回答的半秒左右，按钮可能还在；这时打开的面板可能会显示等待提示。
- 偏好已经就绪之后才失败的草稿读取，如果随后既没有新回复、也没有你发的新消息，卡片要等到这两者之一出现、或者重新加载界面才回得来；草稿本身不会丢。读成功但确实没有草稿，或者形状被这一版拒绝，都是最终结果，不会再重试。
- 退回上一版会保留你选过的选项，但不保留「已继续」状态：点过 **继续作答** 的卡片刷新后要再点一次 **继续作答**。
- 同一条回复里先发一条普通消息、再打 `1B` 这样的答案，这个答案不会算到卡片上。没有东西会丢：卡片还能继续作答，草稿也保留。
- 手机宽度下，在 Paseo 自己的输入框里按 Enter 是换行，请用它的发送按钮。这是宿主的行为。
- 手机宽度下，按 Esc 不会关掉回答卡片；点面板外面可以关掉（约一秒后收起）。这是宿主的行为。**不是选项** 不是关闭卡片的办法：它会把这条回复永久收起，卡片和输入框上方的按钮都不再回来。
- 输入框上方的按钮由 Paseo 绘制，在平板和手机宽度下高 32px；卡片里的选项行和 **发送** 至少 44px。
- 这一版的浏览器检查跑在 Paseo 0.17.5 的界面（`paseo` 命令启动的 web UI）里、无头浏览器下、1280×800 和 390×844、用合成 provider 和真实 provider（Codex），提交 f9f0da30 和 56087f61。整页：点一行会打开那条消息所在的对话，包括已归档的对话和第二台宿主上的对话；**复制** 把消息复制下来、不会打开那一行；**引用** 插进那一行所在的对话，另一个对话的草稿不受影响；已归档对话的 **引用** 会打开对话并复制引用；390 宽下按钮高 44px、都在视口内；简体中文标签和提示正确；没有文字的行（只有空格的消息，显示为 `(image)`）按 **引用** 会给出没有文字的提示；控制台没有插件报错。面板在删掉之前也在这些提交上查过；它不属于这一版。检查过的第二个提交之后，引用改为逐行生成，**引用** 有了自己的空消息提示；两者都有单元测试。之后 `80a0dba` 删掉了头部按钮和面板，`9618fe4` 只收窄引用动作的类型、行为不变。删面板的提交 80a0dbaa 上又跑了一轮浏览器检查：对话头部没有 **我说的话** 按钮、没有面板，左边栏那一行还在；点一行能打开对话和已归档的对话；**引用** 插进那一行所在的对话、另一个对话的草稿不受影响；**复制** 复制消息、不打开那一行；390 宽下按钮 51×44 和 56×44、都在视口内；设置页显示版本 0.17.5.2；控制台没有插件报错。也在 macOS（Apple 芯片）的 Paseo 0.17.5 桌面 app 上查过：隔离运行（用自己的数据目录），通过调试端口驱动，提交 80a0dbaa 和 9618fe47。对话头部没有 **我说的话** 按钮，也没有旁边的面板；点一行会打开对话，包括已归档的对话；**引用** 插进那一行所在的对话，另一个对话的草稿不受影响；已归档对话的 **引用** 会打开对话并复制引用、弹出提示；**复制** 复制消息、不打开那一行；没有文字的消息按 **引用** 会提示没有文字可引用；设置页显示 0.17.5.2；控制台没有插件报错。桌面 app 上没有截图。没有在真实的 iOS／Android 设备上检查，也没有在 Paseo 0.16.x、0.17.1、0.17.2、0.17.3、0.17.4、深色主题、日文界面、其他窗口尺寸上检查。
- 卸载插件会删掉它的设置，请先备份。启动不会删除插件数据目录里的旧文件。

## 隐私与主机上的数据

- Clear Chat 不会把对话内容发到主机之外，不发给 agent 供应商，也不发给其他服务。例外是你自己发出的消息：回答卡片上的 **发送** 会以你的身份，经 Paseo 把一条消息发给当前对话的 agent，和你手打的消息一样。
- **我说的话** 整页从宿主读取对话。**复制** 把消息放到剪贴板；**引用** 把消息插进那个对话的输入框、不发送，插不进时改为复制引用。它不发送任何东西，也没有自己的设置。
- 这一版不读取本机图片、不做代码高亮，也不再注册 provider 副本。
- Clear Chat 自己唯一的联网是安装时的 `npm ci`。
- **报告问题** 在浏览器里打开 GitHub 表单。你不提交，就什么都不会发出。
- 已有的插件数据目录会留着。这一版不会新建图片库或历史记录。

## 大家常问的问题

**Clear Chat 还绘制对话吗？** 不绘制。步骤行、工具卡、侧边栏、搜索、引用回复、跳转标签和语法高亮都没有了。标题为 **这一轮的改动** 的卡片也没有了。对话显示用 [Better Paseo](https://paseo.sh/plugins/roundreddot/better-paseo)。

**为什么看不到回答卡片？** 打开 **在包含字母选项问题的回复下显示回答卡片**。最新回复要有编号的问题，每题至少两个字母选项，并且有推荐标记，或有 “reply with”“answer with” 这类要求简短作答的提示。这段回复生成完之后，输入框上方才会出现它的按钮，点按钮打开卡片。

**哪些回复会被认成题？** 带编号的问题，每题至少两个字母选项，并且有推荐标记或简短作答的提示。代码块和引用不算。

**要改现在的 agent 设置吗？** 不用。这一版不加 provider 副本。以前的粘贴图片处理没有了。

**为什么「我说的话」里少了一条消息？** 整页列的是本机各对话里、它判断成你说的话、并且属于今天的消息。开头是机器形状的消息（宿主信封、指令标签、粘贴的上下文头、委派包裹）会计成机器消息；更早的日子不列；整页会跳过别的 Agent 开的对话，直接打在这种子对话里的字也不列。中途插进来的消息按标记之间的正文列出。

**支持哪些 Paseo 版本？** 0.16.0 或更新。在 Paseo 0.15.x 上这一版无法正常运行，请留在 Clear Chat 0.15.4.x。Paseo 0.13 和 0.12 的旧安装路径见[安装](#安装)；0.13 的命令仍未实测。

**卸载插件后设置会怎样？** 会跟插件一起删掉。请先备份。见[从 Beautiful Chat 升级](#从-beautiful-chat-升级)。

**Clear Chat 会把对话发到别处吗？** 不会，除了你自己发出的答案，那和手打的消息一样经 Paseo 发出。完整说明见 [OVERVIEW](OVERVIEW.zh-CN.md)。

## 常见问题

| 问题 | 怎么办 |
|---|---|
| 用 Cafe 插件安装失败。 | 用[安装](#安装)里的 Paseo CLI 命令重试，仓库和版本标签保持不变。Clear Chat 用 `npm ci --include=dev --ignore-scripts` 安装依赖，所以运行 daemon 的主机上要有 Node.js 和 npm，网络也要能连到 npm 仓库。如果代码目录是你自己管理的，请先在那里运行 `npm ci --include=dev --ignore-scripts` 再重试。 |
| 安装停止，提示插件需要更新的 Paseo 版本。 | Clear Chat 0.17.5.2 需要 daemon 主机和所有连接的应用都用 Paseo 0.16.0 或更新版本。在 Paseo 0.15.x 上请留在 Clear Chat 0.15.4.x。更旧的宿主见[安装](#安装)。 |
| Clear Chat 提示需要插件 RPC、设置页面、设置注册和请求处理。 | 把运行 daemon 的主机和所有连着的应用都更新 Paseo，再重新加载 Clear Chat。需要的版本写在 `paseo-plugin.json` 里。 |
| 插件注册失败，Clear Chat 启动不了。 | 更新 Paseo，再重新加载 Clear Chat。还不行的话，先备份插件设置，再用 CLI 重新安装。 |
| Clear Chat 读不到主机上的设置。 | 重新连接主机，在设置页点 **重试**。还不行的话，检查 daemon 能不能访问插件设置文件夹。 |
| Clear Chat 提示设置无效或格式不支持。 | 先备份设置。用一份正常的备份恢复，或在 daemon 主机上修好设置文件，再点 **重试**。Clear Chat 不会自己删掉这个文件。 |
| Clear Chat 保存不了设置。 | 检查 daemon 主机上的写入权限和剩余磁盘空间，重新连接后再改一次。**重试** 只会重新读取设置，不会重发刚才失败的修改。 |
| 设置被另一个客户端不停改动。 | 等另一边改完，再改一次。 |
| Beautiful Chat 的设置没有复制过来。 | 保留 Beautiful Chat 原来的设置并备份。检查两个插件设置文件夹的读写权限和剩余磁盘空间，再重新加载 Clear Chat 重试。复制失败时，daemon 日志里会有一条恢复提示；已经存在的 Clear Chat 设置文件不会被覆盖。 |

如果 Paseo 运行不了构建命令，或加载不了插件包，Clear Chat 就没办法自己显示提示。请检查 daemon 主机上的 Node.js、npm 和 Paseo 版本，再用 CLI 重试。问题还在的话，用设置页里的 **报告问题**，附上恢复提示和你的 Paseo 版本。分享日志前，请去掉私人路径和对话内容。

## 从 Beautiful Chat 升级

1. **备份** Beautiful Chat 的设置。
2. 在 Beautiful Chat 还装着的时候**安装 Clear Chat**。Clear Chat 第一次启动、自己还没有设置文件时，会把 Beautiful Chat 的文件复制过来。
3. **确认**文件到了，再卸载 Beautiful Chat。设置页只显示回答卡片开关和常用回答。复制过来的其他键留在文件里，没有对应控件。

<details>
<summary><b>具体命令、回退方法、复制是怎么做的</b></summary>

下面的命令使用 `PASEO_HOME`，没有设置时用 `$HOME/.paseo`。如果你的 daemon 只用 `--home` 指定目录，请先把 `PASEO_HOME` 设成那个路径。备份或确认失败时请停下。

**1. 备份**

```bash
legacy_backup="${PASEO_HOME:-$HOME/.paseo}/backups/plugin-settings-beautiful-chat-$(date +%Y%m%d-%H%M%S)"
mkdir -p "${PASEO_HOME:-$HOME/.paseo}/backups"
cp -a "${PASEO_HOME:-$HOME/.paseo}/plugin-settings/beautiful-chat" "$legacy_backup"
```

如果没有 `beautiful-chat` 这个设置文件夹，说明你没改过 Beautiful Chat 的设置，这一步可以跳过。

**2. 安装**

```bash
paseo plugin install git:jasonhnd/paseo-clear-chat --ref v0.17.5.2
```

**3. 确认后卸载旧插件**

确认 `${PASEO_HOME:-$HOME/.paseo}/plugin-settings/clear-chat/presentation.json` 已经生成，并且和 `$legacy_backup/presentation.json` 一致。已经存在的 Clear Chat 设置文件绝不会被覆盖。如果文件不存在或内容不同，请保留 Beautiful Chat 和备份，到日志里查看复制错误。

```bash
paseo plugin remove beautiful-chat
```

备份请留着。

**回退**

先备份 Clear Chat 当前的设置，再卸载。卸载 Clear Chat 会把它的设置全部删掉，`update` 不会。如果没有 `clear-chat` 这个设置文件夹，跳过 `cp` 那一行。

```bash
clear_chat_backup="${PASEO_HOME:-$HOME/.paseo}/backups/plugin-settings-clear-chat-$(date +%Y%m%d-%H%M%S)"
mkdir -p "${PASEO_HOME:-$HOME/.paseo}/backups"
cp -a "${PASEO_HOME:-$HOME/.paseo}/plugin-settings/clear-chat" "$clear_chat_backup"
paseo plugin remove clear-chat
```

如果 Beautiful Chat 的设置文件夹已经没了，从升级时的备份恢复。把 `YYYYMMDD-HHMMSS` 换成你备份的时间。已经存在的文件夹绝不会被覆盖。

```bash
legacy_backup="${PASEO_HOME:-$HOME/.paseo}/backups/plugin-settings-beautiful-chat-YYYYMMDD-HHMMSS"
test ! -e "${PASEO_HOME:-$HOME/.paseo}/plugin-settings/beautiful-chat" &&
  cp -a "$legacy_backup" "${PASEO_HOME:-$HOME/.paseo}/plugin-settings/beautiful-chat"
```

然后安装 Beautiful Chat 的最后一个版本：

```bash
paseo plugin install git:jasonhnd/paseo-clear-chat --ref 2bf25e8
```

在 Clear Chat 里改过的设置不会同步回 Beautiful Chat。两份备份都请留着。

**复制是怎么做的**

- 第一次启动时，如果 Clear Chat 还没有设置文件，服务端会把 Beautiful Chat 的 `presentation.json` 复制到 Clear Chat 的设置文件夹。两边的文件都不会被删除或覆盖。
- 复制失败时，错误会记到日志，Clear Chat 用默认设置启动。下次启动会再试。
- 然后按当前的设置格式读取。文件里的回答卡片相关值会留下。这一版不再显示的功能，它们的键仍会被接受，但不会显示成控件。
- 在浏览器里，以前存在浏览器里的偏好会导入一次。以主机上保存的设置为准。
- 复制只认默认的安装 id。用了自定义 `--id`，或者 daemon 目录只用 `--home` 指定的，需要手动复制设置。
